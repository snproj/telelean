## minor_decisions
- **decision:** add-node, change-kind and reorder write a layout that lists every card of the subject (moveInLayout over the board's current order), not appendToLayout on the stored layout
  - **rationale:** With an empty layout.json, appendToLayout would put the new card FIRST: layout ids come before file order, and the Inbox file sorts before Main. Pinning the shown order puts it at the end of its column.
- **decision:** Dependents of a removed .holds also include (a) uses found by a text scan while any file is not freshly checked, and (b) for an axiom .holds, every declaration whose #print axioms lists it
  - **rationale:** D-11: never remove a .holds that others use. So the host may answer needs-confirmation where the drop-zone preview said 'nothing uses it'. Rewrite stays refused in both cases (facts-stale / unsafe). planDelete's brokenDependents uses the same rule.
- **decision:** An axiom n.holds whose #check type is not n keeps the table's status (assumed / pending) but is flagged holds-mismatch + TL114
  - **rationale:** The 6.3 table defines axiom cells without a type check. Flagging still surfaces an axiom that does not assert the statement.
- **decision:** TL115 is emitted for uses-sorry on all three node types; a conditional GOAL also gets proved-goal/TL105
  - **rationale:** The table writes TL115 only in the DERIVATION row and lists 'proved / conditional + proved-goal' for GOAL; read literally and consistently.
- **decision:** Footprint order: node ids, then presup: entries, then axiom: entries, each in #print axioms order
  - **rationale:** Reproduces spyroProvedGraph exactly (nodes before presuppositions).
- **decision:** Footprint drops standard axioms, sorts, predicates and opaque constants/functions; axiom-declared constants/functions and 'other' vocabulary become axiom:<name> + TL103
  - **rationale:** Plan 6.3 lists 'an axiom c : T constant' under 'anything else'; such constants assert existence silently.
- **decision:** existence-commitment also counts the presuppositions of a conditional proof's hypothesis nodes as covered
  - **rationale:** Their statements appear in the theorem's type, so #print axioms legitimately lists their presuppositions.
- **decision:** not-checked is set only on nodes with a binding; code-less cards never show it
  - **rationale:** Lean has nothing to check on a code-less card. The flag would be noise when there are no facts.
- **decision:** Lean build messages get a nodeId (and can make a node ill-formed) only when the file's hash equals the facts' hash; messages inside vocabulary declarations get `vocab`
  - **rationale:** Positions in a stale file are not trustworthy, so the message keeps its file and range without a node.
- **decision:** TL011 is emitted by WP2 unless WP1's parse already reported TL011 inside that block (WP1 does)
  - **rationale:** Plan 6.5 lists TL011 under markup while the brief asks for no-rationale with TL011. De-duplicating per block keeps exactly one.
- **decision:** Blocks outside any subject (TL120) and later duplicate-written-id blocks (TL006) are not nodes; with TL017 the first block owns the declaration, and the second is still shown with a status
  - **rationale:** ProjectModel.nodes doc: 'duplicates are reported, the first wins'; a node needs a subject.
- **decision:** subjectGraph: vocabulary = the subject's own items with usedBy filtered to its nodes; project-level diagnostics (files outside every subject, e.g. TL120 in Model.lean) are shown on every board; an unknown subject yields an empty graph
  - **rationale:** A board only shows its subject, but project-level problems would otherwise be invisible. Not throwing helps when a subject disappears (undo of create-subject).
- **decision:** Refs to a structure field keep the field's own name (e.g. S.Rec.past); `uses` maps it to the parent item
  - **rationale:** Keeps the 'ref text is a suffix of its name' property; the webview can fall back to a prefix lookup for the gloss.
- **decision:** Kind changes of nodes with TL101/TL113 change only `type:`; a change-kind rationale is written only for a change to ASSUMPTION; an empty rationale in edit-node removes the field
  - **rationale:** Never touch malformed bindings' Lean. 'Optional rationale for a change to ASSUMPTION'.
- **decision:** Labels: 'Set stance: none (…)' / 'Set source: none (…)' when cleared; '← 1 premise' singular; sentences cut to 60 code points including the ellipsis
  - **rationale:** Grammatical forms of the 6.2 templates.
- **decision:** The planner applies Lean ops first (pristine text, so fact spans stay valid), then block edits, re-parsing between steps and finding blocks again by mapping their start offset
  - **rationale:** Several primitives can touch one file without overlapping edits or duplicated id lines.
- **decision:** graph.json: objects accept unknown properties (zod looseObject); format_version must match ^1\.\d+$; no $id; proved footprint may contain axiom: entries; record keys sorted; files[].sha256 '' when the hash is missing; semantic.stale computed from the export's hashes (a failed module is not stale)
  - **rationale:** Consumers must ignore unknown properties (minor versions add fields), and no made-up URLs are used. Determinism and accurate staleness.

## integration_notes
Entry points. buildProjectModel(input) and subjectGraph(model, subject, {version, layout, semantic}) in project/. planAction / planKindChange / planDelete in edit/. toGraphJson(model, {generatorVersion, generatedAt, fileHashes}) in export/.

Zod schema. graphJsonSchema and graphJsonJsonSchema() live in core/src/export/schema.ts and are NOT exported from @telelean/core (keeps zod out of the webview bundle). Import the file by path where you need validation, e.g. '../../../core/src/export/schema.js' from packages/runner/src/workspace/.

Edges are not a ProjectModel field. subjectGraph and toGraphJson compute them once per model object (WeakMap cache) and recompute from the model's public fields (nodes, ownerOfDecl, declFacts) for copies.

model.declFacts holds the USABLE facts: every declaration of fresh files, plus the declarations of stale files whose current keyword agrees with the facts' kind. model.freshFiles requires module state 'fresh' and a matching hash.

planKindChange previews with modelSemantic(model): 'fresh' when every model file is fresh, 'stale' when facts exist otherwise, 'unavailable' without facts. Its impact equals kindChangeImpact on that graph, with dependents extended by untracked users.

The host can answer needs-confirmation even when the webview's drop-zone impact said none: text-scan uses while files are stale, and axiom-list users. The webview must handle actionResult needs-confirmation (the protocol already supports it).

EditPlan.layout is the full column order for add-node, change-kind and reorder; delete uses withoutIds; create-subject uses emptyLayout. EditPlan.archive reasons are 'deleted' or '<From> -> <To>' (e.g. 'Goal -> Assumption').

Label formats follow plan 6.2.

The core webview bundle now includes the project/edit/export modules (pure TS, unicode regexes, ES2023).

Fixture hashes. spyro-facts.json: Model.lean=sha-model-root, Model/Spyro/Main.lean=sha-main, Model/Spyro/Vocabulary.lean=sha-vocabulary. spyro-proved-facts.json: Main=sha-main-proved. spyro-derived-facts.json: Main=sha-main-derived; it pairs with test/fixtures/project/spyro-derived/Main.lean = the proved overlay plus derivation dark-and-pg and goal pg-again := dark_and_pg.holds.2.
