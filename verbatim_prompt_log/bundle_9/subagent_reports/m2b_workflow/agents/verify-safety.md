## issues
- **severity:** major
  - **package:** runner
  - **description:** scripts/smoke-claude.mjs (M0's live smoke, still in the repo and owned by the integrator in M2) starts real Claude sessions by default. It has no --live switch and no environment double opt-in, and it never sets TELELEAN_NO_REAL_CLAUDE for itself. A plain `node scripts/smoke-claude.mjs`, or the documented usage line without --dry-run, at once runs scenarios a, b and c on the user's subscription: Haiku, up to 8 turns each, plus a 75 s blocking question. This fails the lens requirement that the walkthrough and smoke scripts refuse live mode without an explicit switch. It also contradicts the M2 plan's tripwire 3, 'No default anywhere starts a session'. Today only the user's standing rule, or TELELEAN_NO_REAL_CLAUDE=1 exported in the shell, prevents it. walkthrough-claude.mjs, by contrast, is dry by default and needs both --live and TELELEAN_WALKTHROUGH_LIVE=yes; I checked its code, and its 4 refusal tests passed in my run.
  - **evidence:** /home/zhengyew/telelean/scripts/smoke-claude.mjs:70 `'dry-run': { type: 'boolean', default: false }`; :89 `const DRY = argv['dry-run'];`; main() :546 `if (DRY) { … return 0; }`, then :550 `log('LIVE RUN: this spends a little of the Claude subscription quota.')` followed by the live scenarios. There is no `live` option, no environment check and no TELELEAN_NO_REAL_CLAUDE in the file. I established this by reading the code; running it without --dry-run is forbidden.
  - **suggested_fix:** Make it dry by default. Make it live only with --live AND an environment variable (e.g. TELELEAN_SMOKE_LIVE=yes), refusing before any binary is resolved, exactly like walkthrough-claude.mjs lines 72-79. Set TELELEAN_NO_REAL_CLAUDE=1 for itself when not live. Add a refusal test modelled on packages/runner/test/run/walkthroughScript.test.ts, always passing a fake --binary.
