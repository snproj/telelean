# fix-3:extension+webview (agent af6209b79ffef19f7)

## summary
I fixed the one minor issue in my paths. smoke.mjs's leftover-unit check (6c) can now tell when an empty telelean-* scope belongs to the current run, and it stops it. The runner change that would stop such scopes from being left in the first place is outside my paths, so it is in open_issues.

What changed: a new helper module, packages/extension/scripts/smoke-units.mjs, finds this run's extension host pids and Claude run ids. It reads them from the test instance's own logs in its isolated user-data/logs (the "Extension host with pid N" lines and the "runId" entries) and from the run folders under globalStorage/telelean.telelean/runs. It then matches runLean's unit names against them: telelean-tlws<pid>_<w>_<k>-<n>.scope (refreshes), telelean-p<pid>-<n>.scope (runLean's default run id) and telelean-<runId>-<n>.scope (Claude runs). Check 6c in smoke.mjs now treats a unit as this run's if a process in it points into the run's profile (as before) or if its name matches. Any unit of this run is stopped, plus reset-failed. If it still has processes, the check fails (as before). If it is empty, the script waits up to 2 s for systemd to end it, then stops it and prints a new non-failing WARN line, which is also saved in smoke-summary.json. Units that belong to other processes are only noted.

The issue's guess about the cause is wrong. The scope was not left by the extension host exiting mid-refresh. The user journal shows telelean-tlws1979697_2_1-23.scope "Started" at 02:50:30.013. That is 4 ms after runs.test.ts closed the runs_model board at 02:50:30.009, which disposed that workspace and cancelled refresh 1. The host kept running until 02:50:45.5. There was never a "Consumed CPU" line for the scope, and it only stopped at 02:53:25 when the verifier stopped it by hand.

The actual cause is in runLean. On a cancel, its terminate() SIGKILLs systemd-run while systemd-run is still waiting for its scope to be created. systemd 255 then puts the dying, not-yet-reaped process into the new cgroup. The kernel silently skips a process that is exiting, so the cgroup is never populated and systemd never gets the "empty" event. The scope then stays active/running with 0 tasks. runLean's close handler only runs `systemctl kill` on it, which cannot end an empty scope.

I reproduced this with a probe in my scratch folder. When systemd-run was killed 9 to 19 ms after starting, with the caller busy for 100 ms, 32 of 45 scopes were left active, with 0 tasks and 'populated 0'. `systemctl --user kill` left 11 of 11 such scopes active. `systemctl --user stop` removed them all.

I also tested the fix end to end. I made a real stuck scope named after the first smoke instance's host pid (telelean-tlws1996279_99_1-991.scope) and ran the full smoke. Both instances passed. smoke.mjs matched the scope to host 1996279, stopped it and printed one WARN line. Nothing was left behind afterwards. I did not touch any code that goes into the extension bundle, so I did not rebuild, and the dist/ hashes are unchanged.

## open_issues
- Runner (outside my paths: packages/runner/src/lean/runLean.ts and lean/systemd.ts), for the core-runner fixer. This is the real cause of the leftover scopes, and it is not the extension host exiting. runLean's terminate() calls child.kill('SIGKILL') (line 403). When a cancel or abort arrives while systemd-run is still waiting for its scope job, systemd 255 puts the dying, unreaped process into the new cgroup, and the kernel skips it without an error. The scope then becomes active/running with a cgroup that never had a process, and no 'empty' event ever comes. The close handler's fallback after its 2 s settle loop (line 483-485) is `systemctl kill`, which cannot end an empty scope. Suggested fix: add a stopUnit helper (`systemctl --user stop <unit>.scope`) and call it, followed by reset-failed, when the scope is still active or deactivating after the settle loop. Alternatively, always stop the unit after a cancel or timeout. An extra option: in terminate(), wait for the 'child-pid' status record before killing, so systemd-run is never killed while the scope is being created. Evidence: the journal for telelean-tlws1979697_2_1-23.scope (Started 02:50:30.013, 4 ms after the runs_model board closed and its workspace was disposed at 02:50:30.009; Stopped 02:53:25, by the verifier); the probe /tmp/claude-1002/-home-zhengyew-telelean/03a29d54-7342-40e3-b5f0-2697a62c93ef/scratchpad/turn9/fix3-extension-webview/probe-race.mjs (32 of 45 stuck; kill does not clear them, stop does).
- Runner, optional: the case the issue described, where the host really does exit within milliseconds of such a cancel, never reaches the close handler. A once-per-process sweep in the runner would cover it: on the first runLean or preflight, stop telelean-tlws<pid>_* and telelean-p<pid>-* scopes whose <pid> is no longer running and whose cgroup is empty. The extension has no runner API it could call for this, so I made no change on the extension side.
- After any runner change, rebuild the extension bundle (root `npm run build`), because packages/extension/dist/extension.js bundles the runner. I did not rebuild now: I changed no bundled source, and a rebuild during the other fixer's edits could bundle unfinished runner code.
- Low-priority isolation note (an existing behaviour, not changed): smoke.mjs does not point the test instance's TMPDIR at its profile. During my run, the shared /tmp/vscode-typescript1002 folder's mtime changed at 03:12:19, while the first test instance was shutting down; no new entries remained. Redirecting TMPDIR needs care, because a long scratch path could push Chromium's singleton socket path past the 108-character limit.

## minor_decisions
- **decision:** An empty leftover unit of this run is stopped and reported as a non-failing WARN, not a FAIL. A unit of this run that still runs a process is still a FAIL.
  - **rationale:** The empty scope comes from a known runner/systemd race that is harmless (0 tasks). Failing on it would make the smoke fail at random until the runner is fixed. Stopping it ends the accumulation the issue complained about, and the WARN line, which is also in the summary JSON, keeps it visible.
- **decision:** Units are matched not only by the requested tlws<pid>_* refresh names but also by p<pid> (runLean's default run id) and by Claude run ids. The run ids come from 'runId' entries in the instance's logs and from the run folders under globalStorage/telelean.telelean/runs.
  - **rationale:** Claude-run checks that are cancelled right after the spawn hit the same race. All these ids come only from this run's isolated user-data folder, so units of other builders are never claimed. The unit tests check that a prefix or superstring of a pid does not match.
- **decision:** Host pids are read from the VS Code logs inside the run's own user-data folder (main.log, renderer.log, exthost.log).
  - **rationale:** The hosts are already dead when the check runs, so /proc cannot be used. These log lines are written only by this run's instances, and no change to the tests or the extension was needed.
- **decision:** The matching rules live in a separate module, scripts/smoke-units.mjs, with a vitest unit test. It is imported with `@ts-expect-error`, following test/unit/bundle.test.ts and scripts/build-steps.mjs.
  - **rationale:** smoke.mjs is a top-level-await script that starts VS Code, so its rules could not be unit-tested where they were. Following the existing pattern keeps typecheck green without adding declaration files.
- **decision:** Before stopping an empty unit of this run, wait up to 2 s in total for systemd to end it by itself.
  - **rationale:** This avoids warning about a scope that is merely being torn down. It costs nothing when there is no candidate.
- **decision:** I checked the new path with a stuck scope I made myself, using the same race and a name that matches the run's real host pid, during a full smoke run.
  - **rationale:** The natural leftover appears only sometimes. Injecting one exercises the matching, settle, stop and WARN steps against real systemd state in a real smoke run.
